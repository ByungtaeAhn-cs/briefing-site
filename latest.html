별도 Anthropic API Key 없이 Claude Pro/Max 구독 사용량으로 Hermes를 구동하는 구조임. 내부적으로 공식 Claude Code CLI를 호출하며, Hermes의 Agent Loop·Tool·Approval·Compaction은 그대로 유지됨. Hermes 0.21.4+ 필요, 현재 Experimental 단계임. 지원 모델은 Sonnet 5, Opus 5, Opus 4.8, Haiku 4.5, Fable 5.1이며, Sonnet/Opus 계열은 1M context 경로도 지원함. 단 claude -p / Agent SDK와 같은 과금 계수가 적용되어 인터랙티브 모드 대비 5시간 한도 기준 **약 60% 처리량**에 그친다는 경고 동반.

Codex 프레임은 Context(Projects·Memory·AGENTS.md) → Access(Computer Use·MCP·plugins) → **Repeatable Work**(Skills·Schedules·Hooks·Record/Replay)의 3단계 구분임. 로컬 schedule은 컴퓨터와 앱이 켜져 있어야 한다는 운영 제약도 지적함.

“Claude 구독은 있는데 API 비용 때문에 Hermes 연결을 망설였다”면 꽤 큰 업데이트입니다.
Hermes에서 쓰는 사용량은 일반 Claude Code TUI보다 더 빨리 소모될 수 있습니다.

구독 OAuth 기반 헤드리스 claude -p 호출에 따른 한도 소모율을 수치로 제시한 드문 사례임. 같은 방식으로 파이프라인을 돌리는 독자에게 직접적인 용량 계획 지표임. 로컬 schedule 상시 구동 제약도 Task Scheduler 기반 운영과 같은 문제 계열임.
