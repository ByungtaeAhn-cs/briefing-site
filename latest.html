핵심은 **하니스 흡수론**. 오케스트레이션 레이어가 외부 스캐폴딩으로서의 독립성을 잃고 모델이 이를 학습·흡수하는 방향으로 빠르게 이동 중이라는 정리임. **Meta Muse**는 고성능 모델 출시로 평가함. 앱 버전도 VPN 없이 사용 가능해졌다는 사용 경험을 공유하고, 봇 경쟁은 GrokBot 대 Muse 구도가 강세일 것으로 전망함. xAI 요금제는 하나의 구독으로 4개 서비스를 연동하는 것이 핵심이나 사용량은 많지 않을 것으로 추정함. Notion에 메모리를 두고 GrokBot·Muse·dots를 운용하는 에이전트 구상도 제시함. 소통 창구는 Slack이나 이메일만으로도 충분하다는 견해임.

점점더 구독료는 올라가고 프론티어 회사들의 서비스도 다각화되면서 여기저기 안쓸수가 없게 되는게 현실 같습니다.

자체 하니스 구축에 들인 투자가 얼마나 오래 유효할지 재검토하라는 신호임. 동시에 구독 비용 누적이 실무 격차로 이어진다는 문제 제기임. Claude·GPT 병행 사용자로서 구독 포트폴리오와 에이전트 스캐폴딩 비중을 점검할 계기.

샘호트만, Anthropic의 Git→Scion 전환과 Opus 5.5 모션 그래픽 workflow 공유

LinkedIn 게시물 2건을 요약해 공유함. 바이브코딩 서비스 런칭 영상용 레퍼런스 사이트(launchlibrary.xyz)도 소개함. 일정 문의에는 주말을 우선 검토하고, 수요가 많으면 평일 할인가도 고려하겠다는 답변.

Anthropic의 7명 팀이 5개월에 걸쳐 monorepo를 Git에서 사내 VCS인 **Scion**으로 이전한 사례임. merge 건수는 5월 하루 2,500건에서 9월 3만 건 초과로 증가했고, main 이력은 약 100GB 규모임. CI의 하루 2,500만 checkout을 매번 복제하면 600PB/day가 든다는 계산이 서버 중심 설계를 택한 배경. commit·blame·merge·rebase는 서버가 처리하고, client는 bounded object cache와 파일 배치만 맡음.

저자는 Git mirror 대비 CPU·memory 200배 감소를 제시

Opus 5.5 모션 그래픽 workflow는 3단계 반복 루프로 정리됨. brief·logo·reference를 한 폴더에 모으고, **CLAUDE.md에 프레임 자체 점검 지침**을 넣은 뒤, timestamp를 지정해 장면 단위로 보정하는 방식임.

agent가 일으키는 merge 부하 때문에 VCS 자체를 교체한 첫 대형 사례. agent를 병렬로 운용할 때 Git이 어디서 한계에 부딪히는지 판단하는 근거가 됨. CLAUDE.md에 검수 지침을 넣는 패턴은 Claude Code 작업에 바로 적용 가능함.
